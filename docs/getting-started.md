# 求職起步總覽

> 這一頁是整個知識庫的地圖。如果你才剛開始想「要不要換工作」或「畢業後要找什麼」，從這裡開始，再依自己卡住的階段點進對應頁面。

---

## 一、求職是一條有順序的流程，不是一次性任務

多數人把求職想成「寫一份履歷，然後投出去等通知」，但實際上求職比較接近一個五階段的流程，每個階段解決不同的問題：

| 階段 | 要解決的問題 | 對應頁面 |
|---|---|---|
| 自我盤點 | 我的優勢是什麼、目標產業是什麼 | 本頁第二節 |
| 履歷準備 | 把經歷寫成看得懂、也過得了 ATS 的成就 | [履歷寫作](resume-writing.md) |
| 投遞與經營 | 選對平台、建立能見度 | [求職平台攻略](platforms.md) |
| 面試表現 | STAR 法、技術面試、談薪、反問 | [面試準備](interview-prep.md) |
| 敘事與決策 | 背景敘事、跨領域轉職怎麼包裝 | [跨領域背景敘事技巧](cross-domain-narrative.md) |

跳過自我盤點直接衝去改履歷格式，是最常見的浪費。履歷寫得再漂亮，如果連自己想投什麼職缺都沒想清楚，內容還是會失焦。

!!! note "這五個階段不是嚴格線性的"
    真實的求職過程通常是來回的：面試被問到某個問題答不好，會讓你回頭修履歷；投了一輪都沒回音，也可能代表平台經營或投遞策略需要調整。把這五個階段當成檢查點，不是一次性關卡。

---

## 二、自我盤點：投遞前先想清楚三件事

在打開履歷範本之前，先花時間回答這三個問題。它們看起來像廢話，但決定了後面所有內容怎麼寫。

### 2.1 我要投什麼職缺

這不是「我想找工作」這種籠統的問句，而是要具體到職能與產業。同一份經歷，投軟體工程職缺、投資安顧問職缺、投產品經理職缺，該強調的重點完全不同。哈佛與柏克萊的職涯中心都建議履歷應該依職缺調整，不要完整列出人生經歷，先鎖定方向，才有辦法決定哪些經歷值得放進去、哪些該收起來。

實用的做法是建一張「職缺需求與履歷證據」對照表：把目標職缺公告上寫的每一項能力要求列一欄，對照你目前履歷裡哪一條可以證明，再看看哪些能力目前完全沒有證據支撐。這張表比反覆修飾措辭更能抓出履歷真正的漏洞。

### 2.2 我手上有哪些可以佐證的素材

大多數人低估了自己手邊已經有的素材：專案文件、程式碼倉庫、簡報檔、成績單、社團或工讀經驗，甚至聊天紀錄裡跟主管討論過的決策脈絡。求職準備期最值得花的時間，不是想新的形容詞，而是把這些散落的素材整理成可以隨手引用的「成果庫」。之後寫履歷、寫 LinkedIn、練習面試回答，都是從同一批素材裡抽取不同的切面。

### 2.3 我的時程有多少彈性

求職的節奏會反過來影響你能做的準備深度。如果離職或畢業的時間點還有三個月以上的緩衝，值得花時間打磨履歷、系統性地準備技術面試；如果時間緊迫，優先順序要換成「先把履歷改到堪用、盡快投出去」，細節打磨往後排。誠實評估自己的時間壓力，比套用任何「標準求職時程」都重要。

## 三、心態調整：把求職準備當成一個可以迭代的專案

求職過程中很容易把每一次投遞石沉大海或面試沒有下文，解讀成對自己整體能力的否定。比較健康、也比較有效率的心態是：把履歷、LinkedIn 個人檔案、面試回答都當成「還在迭代的產出」，每一輪反饋（無論是面試官的追問、還是投遞後的沉默）都是用來修正下一版素材的資訊，而不是最終判決。

這個心態轉換也呼應本站在履歷寫作與面試準備兩頁反覆強調的一個原則：**沒有一套格式或答法可以保證錄取，能做的是持續把可驗證的證據講清楚。** 求職平台的 AI 健檢工具、ATS 優化技巧，都只能提高「被看見」與「被正確解析」的機會，不能保證錄取，這件事在[求職平台攻略](platforms.md)與[履歷寫作](resume-writing.md)兩頁都會再次提到。

## 四、常見的求職者類型與各自的起步重點

| 你的狀態 | 起步時最該優先做的事 |
|---|---|
| 應屆畢業生、經歷較少 | 把課程專案、實習、社團經驗整理成成果庫；履歷傾向一頁，教育與專案往前放 |
| 有相關全職經驗，想找同領域下一份工作 | 優先整理量化成果，工作經歷往前放，教育往後移 |
| 轉職或跨領域求職 | 先想清楚敘事主線（見[跨領域背景敘事技巧](cross-domain-narrative.md)），履歷格式傾向混合式而非純功能式 |
| 目標包含外商或國際職缺 | LinkedIn 個人檔案的優先順序要提高，履歷英文版另外準備 |

---

## 五、本頁重點回顧

- 求職是五階段的流程：自我盤點、履歷準備、投遞經營、面試表現、敘事決策，彼此會來回影響。
- 動手改履歷之前，先想清楚要投什麼職缺、手上有什麼素材、時程有多少彈性。
- 建一張「職缺需求與履歷證據」對照表，比反覆修飾形容詞更容易抓出準備上的漏洞。
- 把求職準備當成可迭代的專案，每一輪反饋都是修正素材的資訊，不是最終判決。
- 沒有任何格式、話術或平台工具可以保證錄取，能做的是把可驗證的證據講清楚。
