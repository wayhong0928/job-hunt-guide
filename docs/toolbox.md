## 一、checklist：投遞前自我檢查

勾選狀態只存在你自己的瀏覽器裡，換裝置或清除網站資料就會消失，重要的進度請自行另外記錄。

### 1.1 履歷內容自檢

- [ ] 這份履歷有依目標職缺調整內容，不是同一份履歷投所有職缺？
- [ ] 每一條經歷都寫成了「成果」，而不是「職責清單」？
- [ ] 至少大部分條列套用了 APR 句型（行動＋專案或問題＋結果）？
- [ ] 沒有可信數字的條列，改用可驗證的範圍描述，而不是硬湊百分比？
- [ ] 每個強動詞後面都接了對象、方法與結果？
- [ ] 沒有拼字、日期、聯絡方式的錯誤？
- [ ] 沒有誇大職稱、年資或技術熟練度？
- [ ] 沒有把團隊成果全部寫成個人成果？
- [ ] 沒有洩漏客戶名稱、弱點細節、內部架構或前公司機密？
- [ ] 版面是單欄、標準字型、無圖表，貼進純文字編輯器檢查過順序沒有錯亂？
- [ ] 履歷、LinkedIn、104、Cake 上的日期、職稱、成果彼此一致？
- [ ] 用 AI 工具協助草擬或改寫過的段落，已經自己重讀並修掉罐頭式措辭？

### 1.2 LinkedIn 個人檔案自檢

- [ ] Headline 清楚陳述目前或目標角色、點出一到兩個核心技能、暗示能帶來的價值？
- [ ] About 開頭兩三句話就有具體重點，不是模糊的自我介紹？
- [ ] 目標職缺的關鍵字同時出現在 Headline、About、Experience？
- [ ] Experience 裡的每一筆都是真實的任職關係，不是把客戶或使用者關係寫成工作經歷？
- [ ] Skills 欄位依目標職務優先順序排列，而不是塞滿上限？
- [ ] Featured 區塊放了具體的作品、簡報或專案連結？

### 1.3 104／Cake 自檢

- [ ] 「希望職稱／職類」聚焦相近方向，沒有寫「不拘」或混列不相關職類？
- [ ] 重要專案成就直接寫進對應欄位，不是只放在附件裡？
- [ ] 自傳依「背景定位 → 專業能力與成果 → 應徵動機 → 未來方向」的順序客製，不是從家庭背景寫起？
- [ ] Cake 的作品集或履歷精選內容跟目標求職方向一致，不會讓招募者看不出主要方向？
- [ ] 如果 Cake 履歷還要投外部 ATS，已經另外準備一份單欄無圖片的簡式版本？

### 1.4 面試準備自檢

- [ ] 針對目標職缺，整理過「能力、題型、證據」矩陣？
- [ ] 準備了六到八則涵蓋不同能力面向的 STAR 故事？
- [ ] 每則故事的 Result 段落都有可衡量的佐證，不是空泛的「進展順利」？
- [ ] 針對目標職能（軟體工程／資安顧問／其他）做了對應的技術面試準備？
- [ ] 想好了薪資區間的下限與話術，不是等被問到才臨場想？
- [ ] 準備了至少五題反問問題，聚焦具體事件而不是空泛的「文化如何」？

## 二、AI 提示詞範本

!!! warning "使用前必讀"
    這些範本的目的是提高提問的規格化程度，不是把判斷外包出去。每一段 AI 產出都必須經過你自己的驗證與潤飾，不能直接拿去投遞。貼入任何素材前，先移除真實姓名、公司內部代號、客戶名稱等可回推個人或雇主的資訊。範本中的 `⟨⟩` 都要換成你自己的內容。

### 2.1 履歷條列改寫

```
【情境與輸入】
我要應徵⟨目標職缺⟩，以下是我的一段原始經歷描述：
「⟨貼上你原本的職責描述，愈具體愈好⟩」

【預期產出】
請幫我把這段話改寫成 2-3 個版本的履歷條列，
每一版都套用「行動 + 專案或問題 + 結果」的句型，
盡量凸顯量化的規模、時間或影響；如果我提供的內容裡沒有具體數字，
請明確告訴我還缺少什麼資訊，不要自己編造數字。

【邊界與作業原則】
1. 不要生成任何我沒有提供的具體數字或成果。
2. 不要使用「負責」「協助」這類空泛動詞當開頭。
3. 改寫後請附一句話說明這個版本強調的是哪個面向（技術深度／商業影響／領導力等）。
```

### 2.2 STAR 故事草稿

```
【情境與輸入】
我要準備⟨目標職缺⟩的行為面試，這是我想講的一段經歷：
「⟨貼上你記得的事件經過，包含背景、你做了什麼、後來怎麼樣⟩」

這則故事我希望對應的能力面向是：⟨協作／衝突／成果導向／顧客溝通／判斷取捨／適應學習／失敗反思／主動性，挑一到兩個⟩

【預期產出】
請幫我整理成 STAR 架構的草稿：
- Situation、Task 各 1-2 句話
- Action 是重點，請幫我列出 3-5 個可能被追問的具體判斷點
- Result 請標出哪裡可以放數字或可驗證的結果，哪裡我需要自己補充
- 最後加一句 Reflection：學到什麼、下次會怎麼做不同

【邊界與作業原則】
1. 不要幫我編造我沒有提到的細節或數字。
2. 用「我」而非「我們」描述行動段落。
3. 如果這段經歷內容不足以撐起完整的 STAR，請直接告訴我哪裡資訊不夠，不要腦補。
```

### 2.3 模擬面試官追問

```
【角色】
請扮演一位⟨目標職缺，例如「資安顧問」⟩的資深面試官，
風格直接、會針對模糊或空泛的回答持續追問，但不刁難、不人身攻擊。

【情境與輸入】
我準備了以下 STAR 故事，請你先聽我完整講一次：
「⟨貼上你的 STAR 故事⟩」

【預期產出】
1. 針對我這則故事，提出 3 個你認為最可能被追問的細節問題。
2. 如果我的 Result 段落沒有具體數字或可驗證的結果，指出這一點。
3. 給我一句話的整體回饋：這則故事目前最大的弱點是什麼。

【邊界與作業原則】
1. 不要幫我編造回答內容，追問完就停下來等我自己回答。
2. 回饋要具體指出問題所在，不要只給「很好」「加油」這類空泛鼓勵。
```

### 2.4 跨領域背景敘事草稿

```
【情境與輸入】
我的背景是⟨原本的領域或職務⟩，現在想轉往⟨目標領域或職務⟩。
我目前的具體經驗包括：⟨列出 3-5 項具體專案或工作內容⟩。

【預期產出】
請幫我草擬一段 2-3 句話的定位敘事，說明：
1. 原本背景給了我什麼在目標領域用得上的能力
2. 這個轉換是刻意的一步，不是不得已的備案
3. 我目前還在補強什麼，避免我誇大自己已經具備的能力

【邊界與作業原則】
1. 不要把我原本的經歷直接改名成目標領域的經驗（例如不要把「開發經驗」直接寫成「資安顧問年資」）。
2. 我如果尚未實際做過某件事，請幫我用「正在建立／正在學習」這類措辭，不要寫成已經主導完成。
3. 草稿完成後，幫我列出這段敘事裡有哪些主張是我需要準備具體證據支撐的。
```
